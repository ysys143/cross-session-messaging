# ADR-0009: 세션 간 신뢰 수립(핸드셰이크)

- 상태: Accepted
- 관련 목표: G1, G2, G4, G5
- 관련 ADR: 0004(통신 범위), 0007(원격 신뢰), 0008(이름·주소)
- 작성일: 2026-09-19

## 질문

사용자가 미리 정한 범위 안에서, 두 세션이 메시지를 주고받기 전에 신뢰 관계를 한 번 수립하고, 그 관계가 유효할 때만 메시지를 허용하려면 어떤 방식을 쓰는가?

## 맥락

- **메시지 단위 판정만으로는 부족하다.**
  - Claude의 수신 판정(모드 동등성)과 헤더 검사는 메시지마다 독립적이어서 "이 두 세션은 대화해도 된다"는 관계를 기억하지 못한다.
  - 보류 승인은 메시지마다 사람이 해야 한다(S1).
- **같은 uid 안에서는 위조를 막을 수 없다.** `from-mode`, 헤더, 신뢰 저장소 모두 같은 uid 프로세스가 읽고 쓸 수 있다(S1, S6, T8). 로컬에서 신뢰 수립이 줄 수 있는 것은 **보안이 아니라 동의와 범위의 기록**이다.
- **실측된 실패들**은 관계 기록으로 막을 수 있다.
  - 원격 `from` 경로의 오류 없는 오배송(S5-2)
  - SSH 터널에서 `isolatePeerMachines` 무력화(S5-3)
  - 재시작과 강제 종료 후 남은 레코드(S3)
- **수신 측 검문 지점이 두 런타임 모두에 있다.** `UserPromptSubmit` 훅이 피어·큐 메시지에도 실행되고(S3), 두 런타임 모두 `decision: "block"`을 지원한다(Claude는 `suppressOriginalPrompt`도 지원). 단, Claude는 네이티브 수신 판정을 훅보다 먼저 적용하고, Codex의 차단은 메시지를 없앤다(S6).
- **참고 설계: Orca 페어링**(T4 1절)
  - 서버 공개키 지문을 dispatch에 고정하고, 바뀌면 `peer_changed`로 거부한다.
  - pairing revision으로 오래된 요청을 막는다.
  - 기기 권한을 철회하면 후속 요청이 실패한다.

- **실측(S8, `docs/spikes/S8-results.md`)**:
  - 범위 안 자동 수립, 범위 밖 거부, 1회 사람 승인(macOS 대화상자), 오배송 차단, 재시작·강제 종료 차단, 위조 경계, 철회·만료, 정책 변경 재평가, 원격 지문 고정과 `peer_changed`가 시제품(`tools/mesh/`)으로 모두 동작했다. Claude↔Codex 양방향도 확인했다.
  - 같은 uid 프로세스가 신뢰 저장소를 읽으면 사칭이 통과한다(S8-f). 로컬 핸드셰이크는 동의·범위 기록이라는 전제가 실측으로 확인됐다.
  - 결함: `auto` 모드가 철회를 조용히 되돌렸다. 철회를 고정으로 바꿔 해결했다(사람 승인으로만 해제).
  - 한계: Codex는 헤더 없는 큐 메시지를 사람 입력과 구분하지 못해 `strict_peers`를 적용할 수 없다. Claude는 네이티브 보류가 훅보다 먼저 걸린다.
- **비교 실측(S9, agent-comms)**:
  - agent-comms에도 장치 단위 첫 접촉 동의(`requestDmAccess`, `room_join_request`)가 있다. 공개 room 참가에도 소유자 수락이 필요했다.
  - 그러나 수락 action `room_accept`가 **수신 에이전트의 MCP 도구에 노출돼 있어**, 에이전트가 운영자 지시 한 줄에 수락을 실행했다.
  - 발신 호출에는 시간 초과가 없고(228.7초 관찰, `mesh-session.mjs:357-382`에서 `timeoutMs` 미지정), 유휴 에이전트는 수락할 수 없어 첫 접촉이 끝나지 않았다.
  - cc-peer 기본값 `from-mode=bypass`로 같은 uid의 일반 프로세스 메시지가 bypass 수신 세션에서 자동 실행됐다. 수신 측 검문이 필요하다는 근거다.

- **재개(2026-09-22, 사용자 요청).** 그 사이 바뀐 사실:
  - 로컬에서 "두 세션이 대화해도 된다"는 관계는 이제 범위가 기억한다(ADR-0004 Accepted). 같은 기본 프로젝트면 자동으로 열리고, 다른 프로젝트는 양쪽 폴더가 같은 이름으로 가입해야 열린다. 사람의 동의가 폴더 단위로 한 번 기록된다.
  - 초안이 요구한 발신 측 사전 검사, 상태 보고(`delivered`·`held`·`refused`·`sent-unconfirmed`), fail-closed 훅, 보관 저장소가 xsm에 구현됐다.
  - 사람에게 직접 묻는 수단(MCP elicitation)이 두 런타임에서 동작한다(ADR-0005). 초안 C의 약점이었던 "승인 UI가 없다"가 해소됐다.
  - 초안의 pair·HMAC이 막으려던 실측 실패들은 다른 장치로 막히고 있다. 오배송(S5-2)은 ref 기반 주소와 수신 측 식별로, 재시작 뒤 남은 레코드(S3)는 pid·`lstart`와 대체 id 판정으로 막는다. SSH 터널 격리 무력화(S5-3)는 원격을 소켓 포워딩하지 않는 것(ADR-0007 제안 E)으로 피한다.

## 선택지

### A. 핸드셰이크 없음 (메시지 단위 정책만)

- 방식: 범위 정책(ADR-0004)을 메시지마다 검사한다. Claude 네이티브 정책과 Codex 훅의 모드 동등성만 쓴다
- 장점: 상태가 없다. 구현이 가장 작다
- 단점: 오배송(S5-2), 재시작한 세션, 에이전트끼리의 관계 확장을 막지 못한다. 사람 승인이 메시지마다 필요하다

### B. 정책 기반 자동 수립

- 방식: 두 세션이 같은 scope의 조건에 맞으면 pair를 자동 수립한다. pair는 세션 신원(session id, pid, proc_start)과 정책 해시에 묶는다. 메시지는 pair id와 HMAC을 싣고, 수신 훅이 검문한다
- 장점: 사람 개입 없이 범위를 강제한다. 오배송과 오래된 관계를 보이는 실패로 바꾼다
- 단점: 정책을 잘못 쓰면 범위가 넓어진다. 같은 uid 위조는 막지 못한다

### C. 1회 사람 승인 수립

- 방식: 첫 접촉 때 사람이 `mesh trust approve`로 pair를 승인한다. 이후 메시지는 B와 같이 검문한다
- 장점: 관계 확장에 항상 사람이 개입한다. 메시지마다 승인할 필요는 없다
- 단점: 승인 UI가 없다(CLI). 사람이 없는 흐름에서는 막힌다. 에이전트가 승인 명령을 실행하지 못하게 해야 한다

### D. 세션별 키쌍과 서명

- 방식: 세션마다 키쌍을 만들고 공개키를 교환해 메시지를 서명한다
- 장점: 머신 경계에서 의미 있는 발신 증명이 된다
- 단점: 같은 uid 로컬에서는 개인키도 읽을 수 있어 B, C보다 나은 보안을 주지 못하고 복잡도만 늘어난다

### E. 혼합 (제안)

- 방식:
  - scope마다 `trust = auto | approve`를 두어 B와 C 중에서 고른다.
  - 원격 pair는 SSH 호스트 키 지문을 고정하고 `approve`를 요구한다(Orca의 `peer_changed` 방식).
  - D는 원격에서 SSH 인증으로 대신한다.
- 장점: 로컬은 가볍게, 관계 확장과 원격은 엄격하게 다룬다
- 단점: 정책 언어와 신뢰 저장소를 새로 정의해야 한다

### F. 로컬은 범위로 대체, 원격 신뢰는 ADR-0007로 (제안)

- 방식: 로컬 pair·HMAC을 만들지 않는다. 관계 기록은 범위(기본 프로젝트, 양쪽 가입)가 맡고, 관계를 넓히는 일(새 프로젝트 가입, 위험한 워커 옵션)은 사람의 명시적 행동이나 elicitation 허가로만 한다. 원격 신뢰(호스트 키 고정, 첫 연결 동의)는 ADR-0007에서 정한다. 이 ADR은 Superseded로 닫는다
- 장점: 새 저장소와 정책 언어가 없다. 이미 동작하는 장치로 초안의 목표를 달성한다. 같은 uid 위조는 초안에서도 막지 못했으므로 잃는 보장이 없다
- 단점: 세션 단위가 아니라 폴더 단위 관계다. 같은 폴더 안의 모든 세션이 서로 통하고, "이 세션과 저 세션만"은 표현할 수 없다

## 결정 전에 정할 세부

- 기본 신뢰 방식: `auto`와 `approve` 중 무엇을 기본으로 할지
- 관계를 무엇에 묶을지: session id만(재시작해도 유지, resume 친화) 또는 session id + pid·proc_start(재시작하면 재수립, 더 엄격)
- TTL 기본값
- 원격 pair의 기본값(`deny` 또는 `approve`)
- 차단된 메시지의 보류 저장소를 사용자에게 어떻게 알릴지(Claude는 네이티브 보류 대화상자가 있지만 Codex는 없다)

## 결정 전에 사용자가 정할 것 (재개)

1. `join`/`leave`와 `--dir`에 사람 확인(터미널 또는 elicitation)을 강제하는가.
2. 워커를 부모의 범위 밖 폴더에 띄우는 것을 허용하는가, grant를 요구하는가, 거부하는가.
3. 세션 단위 `deny` 목록을 두는가.
4. 수신 게이트가 살아 있지 않은 발신자를 차단하는가.
5. 0009를 지금 닫는가, 0007 결정 뒤에 닫는가.

## 결정

**F를 택하되, 닫기 전에 네 가지를 고친다**(사용자 결정 2026-09-22).

1. `join`/`leave`는 사람(터미널)이나 MCP elicitation을 거친다. `--dir`는 사람 터미널에서만 받는다.
2. 워커를 부모의 범위 밖 폴더에 띄우려면 `xsm_grant` 허가가 있어야 한다.
3. 세션 단위 `deny` 목록(`config.json`)을 두고, 수신 게이트와 발신 사전 검사에서 확인한다. 해제는 사람만 한다.
4. 수신 게이트는 살아 있지 않은 발신자의 메시지를 막는다.

이 넷을 구현하고 ADR-0007을 구현하면 이 ADR은 Superseded가 된다. 로컬 관계는 ADR-0004의 범위가, 원격 신뢰는 ADR-0007이 맡는다.

### 이전 기록

**pair 핸드셰이크와 HMAC은 보류한다**(사용자 결정 2026-09-20: v0.1 범위).

지금의 동의 모델은 셋이다.
- 훅 설치와 Codex 훅 신뢰
- 범위 규칙
- 양쪽 가입이 필요한 이름 붙인 프로젝트(ADR-0004)

초안의 요건 가운데 이 모델과 무관한 것은 구현했다. 훅 fail-closed, 인터프리터 고정, 발신 사전 검사, 상태 보고, 보관 저장소다. 초안이 밝힌 한계도 그대로 문서에 남긴다. 같은 사용자 권한의 에이전트는 동의 기록을 고칠 수 있고, 봉투 없는 피어 입력은 검문하지 못한다. 워커 승인의 사람 확인이 보안 경계가 아니라는 점도 같은 한계다(ADR-0010).

다시 열 조건: 실사용에서 프로젝트 가입만으로는 범위가 너무 넓다는 사례가 나올 때.


### 2라운드 결정 초안 (기록)

- **E(수정)**. 로컬 pair 수립과 승인은 협조적인 에이전트의 범위 확장을 기록하고 막는다. 신뢰 저장소와 정책 파일을 직접 쓸 수 있는 에이전트는 막지 못한다.
- 동의는 session id(또는 멤버 패턴)에 묶고, 전달 유효성은 pid·proc_start에 묶는다. 결속이 어긋나면 발신 측이 다시 묶는다.
- `auto` scope의 철회는 해당 세션 쌍에만 적용된다. 지속적인 거부는 정책 편집으로 한다.
- Codex 수신자에 대한 범위 강제는 발신 경로가 mesh 도구일 때만 성립한다. Claude prompting 수신자의 봉투 없는 입력도 같다.
- 발신 도구는 수신 훅과 같은 검사(결속, 생존, 정책 해시)를 먼저 하고, 결과를 `sent|held|refused|sent-unconfirmed`로 보고한다. 수신 확인 대기에는 시간 제한을 둔다.
- MAC은 pair, id, from, kind, mode, body를 덮는다. 목적은 헤더 재사용 탐지다.
- 미결 세부: `trust`를 비우면 `approve`(fail-closed), 단일 저장소 범위에는 `auto` 권장 / `auto`는 TTL 없이 생존에 묶고, `approve`와 원격은 승인 시점부터 8h / 원격 기본값 `deny`, 켜면 `approve`와 SSH 호스트 키 지문 고정 / `held/` 색인과 `mesh held list|release`(release는 사람 승인), 차단 시 macOS 알림.

결정 전 확인 결과(`docs/spikes/S8c-g2-results.md`, 2026-09-20):
- S8-c: 피어가 요청한 승인 명령 실행, 신뢰 저장소 편집, 정책 확장을 에이전트가 모두 거절했다(요청당 1회). 거절은 모델 판단이며, 같은 편집을 사람 프롬프트로 요청하자 auto 모드 분류기가 허용했다. 저장소를 보호하는 강제 장치는 없다. 강제가 필요하면 권한 규칙으로 저장소 경로 편집을 막아야 한다(미시험).
- S8-g2: 봉투 없는 피어 입력은 Claude 훅 검문을 통과한다. 훅 입력과 훅 시점의 대화 기록 모두 피어임을 알려 주지 않는다. 네이티브 `hold`만 막지만 mesh 메시지도 함께 막는다.
- 우연 발견: 훅이 예외로 끝나면 메시지가 통과한다(fail-open). 훅은 예외를 잡아 판정을 명시하고 인터프리터를 고정해야 한다.
