## 시험 중에 드러나 고친 것

시험을 따라가면서 나온 문제를 그때그때 고쳤다. 대부분 사용자가 실제로 부딪힌 것이다.

| 드러난 계기 | 문제 | 조치 | 커밋 |
|---|---|---|---|
| 일반 터미널에서 테스트 실행 | 훅이 자기 세션을 식별하지 못하면 범위 검사를 건너뛰고 통과시켰다. 테스트가 개발 세션의 환경변수를 물려받아 이를 가렸다 | 식별 실패 시 피어 메시지 차단, 기존 포인터로 pid 복구, 테스트 러너 환경 격리 | `dbf3c35` |
| `accept` 설정 방법 누락 | 문서에 방법이 없었다. 프로젝트 설정에서는 이 키가 적용되지 않는다는 것도 실측으로 알았다 | 1.1절, 손 편집 우선 | `1caa583`, `3a14d0d` |
| `xsm install` 멱등성 질문 | 반복 설치마다 백업이 쌓였고, `--dry-run`이 파일을 썼고, `--python` 생략 시 고정이 덮였다 | 변경 없으면 쓰지 않음, 서식 보존 | `802d922`, `8788115` |
| 같은 질문 | 이전 커밋이 다른 작업의 `--python` 기능을 조용히 되돌렸다 | 복원 | `802d922` |
| 다른 훅의 잡음 | 홈에 있던 상대 경로 Stop 훅이 매 턴 오류를 남겼다 | 1장에 점검 항목 | `d420aee` |

| 4-6 지시 부족 | 세션 C를 띄우는 방법이 없었다. 거부 문구가 부정확했고, 관찰 터미널의 목록이 전부 `out-of-scope`로 보였다 | 4.1~4.4절, 문구 수정 | `12e4cca` |
| 오래된 목록으로 망설임 | 발신 세션이 대상을 모른다며 되물었다 | 이름이 안 맞으면 현재 세션 목록을 돌려줌 | `e3d29f4` |

| `xsm who`/`list`를 명령으로 | 셸 명령을 매번 지시해야 했다 | 슬래시 명령 5개, 설치기가 함께 넣음 | `c2dd9c5` |
| 추론 비용 | 명령 지시의 조건문 때문에 모델이 판단했고, 목록 대신 요약을 보였다 | 복사만 하는 지시와 `--compact` 출력. `/xsm-who` 5.8초 → 1.3초, 사고 0 | `c7c5458` |

실측으로 새로 확인한 사실:

- `crossSessionInbound`는 **프로젝트 설정에서 무시된다.** 사용자 설정 파일이나 `--settings`에서만 적용된다.
- 슬래시 명령은 `--setting-sources project,local`로 띄운 세션에서는 로드되지 않는다.
- 명령 파일의 `model:`은 이 버전에서 무시된다(별칭과 전체 ID 모두).
- 셸 모드(`! 명령`)는 모델 턴을 만들지 않는다.
- `--name` 없이 띄운 세션은 폴더 이름 + 접미사(`derived`)로 이름이 붙고, `/rename`해도 ref는 그대로다.
