# Salix 조사

Salix는 Comma(24시간 개인 에이전트 제품)의 에이전트를 돌리는 분산·다중 사용자 하니스다. 자체 에이전트 루프가 있고, 에이전트마다 외부 런타임으로 Codex나 Claude Code를 지정해 사용자 기기에서 돌릴 수 있다. 플랫폼이 Codex·Claude Code를 갈아 끼울 수 있는 실행기로 다루는 사례다. 본체는 공개되지 않아 문서의 주장을 검증할 수 없다.

- 작성일: 2026-10-03
- 출처(모두 2026-10-03 조회):
  - 문서: `https://comma.surf/docs/salix`의 개요, `agent-runtimes`, `devices`, `loops`, 그리고 `https://comma.surf/` 첫 화면 (Jina Reader)
  - 저장소 메타데이터: GitHub API `repos/AFK-surf/spinfoam`, `orgs/AFK-surf/repos`
- 방법: 문서 열람만 했다. 공개된 Spinfoam 소스도 읽지 않았다.

## 1. 구조

- **언어:** Elixir(Erlang VM)와 Lean. 에이전트마다 Erlang 경량 프로세스 하나이고, 일부가 실패하면 재시작하고 나머지 에이전트는 계속 돈다.
- **배치:** 에이전트를 클러스터 노드에 배치하고, 클러스터가 바뀌면 옮긴다. 노드를 넘어 에이전트 사이 메시지를 전달한다. 클러스터는 노드 수백 개까지 간다고 한다.
- **실행 위치:** 읽기, 계획, 쓰기, 연결된 앱 호출은 샌드박스 없이 하니스 안에서 한다. 컴퓨터가 필요할 때만 클라우드 VM을 깨운다. VM은 저장소를 유지하고, 일이 끝나면 다시 잔다.
- **검증 주장:** 턴의 다음 단계와 데이터가 흐를 수 있는 곳 같은 제어 결정을 기계 검증 증명이 붙은 Lean 코드로 실행한다고 한다. "샌드박스 하나 분량의 CPU와 메모리로 에이전트 수백 개"라는 주장도 있다. 둘 다 검증할 수 없다.

## 2. 외부 런타임 (`agent-runtimes`)

- 기본은 Salix 자체 에이전트 루프다.
- 에이전트마다 Codex나 Claude Code를 외부 런타임으로 지정할 수 있다. 그러면 에이전트가 사용자가 고른 기기에서 그 런타임으로 돈다. **Salix는 메시지 전달과 대화 보관을 계속 맡고**, 런타임은 기기에서 일을 한다.
- 외부 런타임은 사용자의 ChatGPT·Claude 구독이나 API 키를 쓴다. Salix는 자격 증명이 아니라 계정 참조만 가진다.
- 기기가 꺼져 있으면 그 에이전트의 일은 기다리거나 오류로 실패한다. 다른 기계로 옮기지 않는다.
- 사람이 이미 띄워 쓰고 있는 TUI 세션에 붙는다는 말은 문서에 없다. Salix가 런타임을 직접 구동하는 것으로 보이나 확인하지 못했다.

## 3. 기기 (`devices`)

- Linux·macOS 기기를 연결하면 에이전트가 그 위에서 명령을 실행하고 파일을 연다. Comma Mac 앱이 Mac을 기기로 연결한다.
- 처음에는 읽기 전용이다. 더 넓은 권한은 사람이 허락해야 하고, 언제든 회수할 수 있다.
- 기기가 없으면 영구 저장소가 있는 클라우드 VM을 깨운다.

## 4. Loops (`loops`)

- 받은편지함, 저장소, 피드 같은 것을 24시간 감시하다가 변화가 있을 때 행동하는 작은 프로그램이다. 상시 켜 둔 샌드박스가 필요 없고, 필요할 때만 에이전트의 본 루프를 깨운다. 조용한 시간에는 모델 토큰을 쓰지 않는다.
- 에이전트가 C로 쓰고, Spinfoam이 eBPF로 컴파일해 클러스터에서 에이전트 곁에 배치한다. Loop 하나가 수 KB에서 수십 KB의 메모리를 쓴다.
- 빠른 판정 모델(예: Jev)로 외부 데이터를 분류해, 큰 모델을 부르지 않고 "이 메일이 사람에게 필요한가"를 정한다.
- 할 수 있는 일은 정해진 목록뿐이다: 읽기 도구, 기기·환경 도구, 웹 요청, 연결된 앱, 에이전트에게 알림. 만든 사람의 권한 이상을 갖지 않는다.
- 다른 시스템이 API나 Loop별 비밀 webhook URL로 이벤트를 보낼 수 있다. 상태는 체크포인트로 저장한다.
- **깨우기 제한:** 10분 동안 에이전트를 깨울 수 있는 횟수에 한도가 있다. 한 시간 내내 한도에 걸려 있으면 Loop가 멈춘다. 장애 후 재시작은 시간당 3회까지이고, 넘으면 멈추고 에이전트에게 알린다.

## 5. 공개 상태

- Salix 본체는 공개 저장소가 없다. Comma의 상용 제품 내부다.
- 공개된 것은 Loops 런타임 Spinfoam이다: `AFK-surf/spinfoam`, MIT, Rust, 2026-09-16 생성, 별 2개, 마지막 푸시 2026-09-20.
- 같은 조직에 `open-agent`(별 1,028개, "Claude Agent SDK, ChatGPT Agents, Manus의 오픈소스 대안")와 `OpenBridge`(별 431개)가 있다.

## 6. xsm에 대한 시사점

| 판단 | 내용 |
|---|---|
| 같은 결론 | 기기 권한을 읽기 전용으로 시작해 사람이 넓히고 언제든 회수하는 것은 xsm의 동의 모델과 같다. 꺼진 기기에는 실패하고 다른 기계로 옮기지 않는 것은 xsm 원격(ADR-0007)과 같다 |
| 해당 없음 | 대화는 Salix가 보관하고 런타임은 실행기다. Buzz의 `buzz-acp`와 같은 소유 모델이라, 사람이 띄운 세션끼리라는 xsm의 영역과 겹치지 않는다 |
| 참고 | Loops는 ADR-0014의 "세션이 아닌 발신자는 보낼 수 없다" 문제를 푸는 방식이다. 작은 감시 프로그램이 상시 돌다가 필요할 때만 에이전트를 깨운다. xsm에 들이면 상주 프로세스가 생기므로, 보드처럼 xsm 밖의 선택 구성 요소로 둬야 한다 |
| 참고 | 깨우기 횟수 한도와 한도 지속 시 일시정지는 ADR-0005 critic이 요구한 멘션 폭주 상한과 같은 장치다 |
